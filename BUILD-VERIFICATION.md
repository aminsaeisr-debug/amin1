# seed-mas 4.2.1 — Build & Validation Notes

## Toolchain and compatibility

- Android Gradle Plugin: 9.4.0
- Gradle Wrapper: 9.6.0
- JDK: 17
- compileSdk: 36
- minSdk: 26
- targetSdk: 36
- applicationId: `com.srooyesh.seedcounter`
- versionCode: 14
- versionName: `4.2.1`

AGP 9.x provides built-in Kotlin support, so this project intentionally does not apply the legacy `org.jetbrains.kotlin.android` plugin separately. The module relies on `compileOptions` Java 17 alignment and does not reference the KGP-only `JvmTarget` type.

## Main-screen settings

All user-adjustable settings are kept on the main screen in one settings card. The settings icon performs in-page scrolling only and does not open a separate settings activity. CameraActivity has no settings controls; it only exposes the current scan mode/state and the configured recognition frame summary.

## Security and signing

The insecure hardcoded-password keystore workflow is absent. Release signing runs only when the required GitHub Actions secrets are supplied. Local signing material is generated by `scripts/generate-keystore.sh` and ignored by Git; generated keystores and Base64 files must never be committed.

## Data and scanner fixes

- ExportTest clears the test database and relevant legacy preferences before creating its fixture, checks the `seed-mas-report_*.xlsx` prefix, and avoids `Thread.sleep`.
- BOTH recognition resets the older stability tracker when the pair window expires, preventing a permanent wait state.
- New records inherit the owning session's business date so an older active session cannot export new rows under today's sheet date.
- The low-level database `createSession` path never silently closes another active session; it refuses a second active session. The repository remains the normal creation boundary.
- Legacy SharedPreferences migration is lazy and guarded against repeated execution. In app entry points, repository calls are performed from `Dispatchers.IO` coroutine paths, so migration work is not performed on the UI thread.
- Backup settings are staged during the SQLite transaction and written to SharedPreferences only after the database commit, avoiding an intentional cross-store transaction mismatch.
- Camera viewport readiness retries instead of throwing immediately; OCR element candidates fall back to the line bounding box when an element has no own box.
- Settings date-output sanitization guarantees that the selected output format has at least one corresponding date column.
- Excel column generation rejects non-positive indices.
- Release R8 rules keep only the scanner/runtime surfaces that require explicit preservation; application-wide keep-all rules were removed.
- Added focused unit tests for storage normalization, Excel column selection/values, settings sanitization, Persian-date conversion, ROI mapping, candidate grouping, plus instrumented backup/settings/export tests.

## CI/CD

The checks job runs unit tests and, for a manual release dispatch, builds and verifies the signed release APK. The connected-tests job runs only for push/debug flows, builds the debug APK while running Android-emulator tests, and uploads that already-tested APK. Release publication depends only on the verified release build; debug publication depends on the emulator-tested debug build. Neither publication path rebuilds the selected APK. Release APKs are verified with `apksigner` before publication, and the checks job fails if signing material is present in the repository working tree.

Current action pins in the workflow are:

- `actions/checkout@v7`
- `actions/setup-java@v6`
- `gradle/actions/setup-gradle@v6`
- `actions/upload-artifact@v7`
- `actions/download-artifact@v8`
- `gradle/actions/dependency-submission@v6`

Dependabot checks both Gradle and GitHub Actions weekly, with a five-PR limit per ecosystem. Workflow concurrency is separated by ref and event type so a push cannot cancel a manual release build.

## Added tests

- `StorageTest`: Persian/Arabic digit normalization, non-digit stripping, barcode whitespace handling, and search-query normalization.
- `ExportTableModelTest`: date-column selection, row-value mapping, and empty-selection fallback.
- `SettingsStoreTest`: valid defaults, range sanitization, and committed preference replacement.
- `BackupCodecTest`: backup payload coverage, round-trip import, and duplicate-safe merge; JSON key assertions use valid Kotlin string literals.
- `SeedRepositoryTest`: active-session exclusivity/idempotency, session-date ownership, and packet-length validation.

## Deliberate non-migrations

Room, Kotlin DSL, Compose screenshot testing, and a full SettingsRepository/Flow rewrite are intentionally not introduced in 4.2.1. They are architectural migrations rather than required corrections for the requested warehouse workflow, and changing them together would increase regression risk.

## Validation limit in this authoring environment

Static source/resource/security validation was completed locally. A full Gradle build could not be executed in this execution environment because the Gradle 9.6.0 distribution could not be downloaded (`services.gradle.org` DNS resolution is unavailable). The project therefore treats GitHub Actions as the clean-network build and device-test path for the release.
